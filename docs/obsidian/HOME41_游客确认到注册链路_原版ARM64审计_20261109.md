已知的不同链路：ApiManagerLogin.AtuhRegisterUser +0x1D2F8DC；ApiRequestAuthRegisterUser.SerializeRequestParameter +0x1D334A4；ApiRequestAuthRegisterUser.CallAfterResponse +0x1D33294；公共响应 basic 经 +0x1D2BA64 调用 UDManager.SetBasic +0x1D763D0。注册专属响应包含 UUID 但不直接包含 UTID。basic.utid 属于 UD_Basic 的 managed string 成员，不得与 UUID、CID 或 SUPID 混同。

## 3. 未闭合证据链与优先事项

已闭合流程：原版游客确认 Phase 23 → 第一层「是」 → ConfirmGestAccountFirst → 第二层「以游客身份开始使用」 → ConfirmGestAccountSecond。

缺口：后继 UI/Action 回调所有权 → 注册请求序列化 → 注册成功回调 → CreateToken/Login → ResponseParamCommon.basic → basic.utid → 六位 HOME ID 显示对照。

下一步优先：
1. 静态追踪 0x1DEB3C0 的对象所有权、调用者及异步回调，不能靠函数名字猜客户端注册成功。
2. 后续动态 UI 和网络验证优先在**用户可持续保有的私人 Android/AVD** 上完成一次；不建议仅为截图反复点击 GitHub 临时模拟器的账号创建按钮。
3. 只在私有环境保留原文身份信息。公开 Actions 最多保存方法计数、是否成功和匿名阶段标识；严禁将 Token、UUID、UTID、HTTP 响应体与注册后原图提交公开仓库。

结论：**官方游客两层确认已真实通过；注册请求、服务器响应和首次 basic.utid 尚未闭合。**
