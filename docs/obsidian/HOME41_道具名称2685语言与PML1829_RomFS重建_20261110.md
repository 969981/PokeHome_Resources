## 1. 上游是哪个 HOME 文件？

NCA 文件树根：`57b83ea8c0af21ef26e2519b9580b373_NCA/`。

| 原始位置（相对 NCA） | 作用 | 输出 |
|---|---|---|
| `1/bin/message/<locale>/megaturtle/itemname.tbl` | 语言标签 `ITEMNAME_nnn` 和 AHTB FNV64 hash | label/hash |
| `1/bin/message/<locale>/megaturtle/itemname.dat` | 语言文字、原始偏移、flags | 每语言 2685 行 `itemname.csv` |
| `1/bin/pml/item/item.dat` | ItemID→记录索引、48B Item8 属性 | `item.id_lookup.csv`、`item.semantic.csv` 等 |
| `1/bin/pml/item/item_hash_to_index.dat` | 与名称标签哈希不同的独立 16B 索引行 | `item_hash_to_index.csv` |
| `0/main.elf` | 原生加载、Item Getter、Bag/Pouch/Sprite 消费者 | 静态代码证据 |
| `1/bin/appli/icon_item/bin/icon_item.arc` | UI 纹理资源容器 | **不直接作为 item_id→PNG 的证明** |

`<locale>` 必须按这 11 个实际目录读取：`Simp_Chinese`、`Trad_Chinese`、`English`、`JPN`、`JPN_KANJI`、`Korean`、`German`、`French`、`Italian`、`Spanish`、`LATAM`。

> [!warning] 原始文件与转换文件不能混淆
> `<NCA>/1/bin/...` 是已提取的 RomFS；`Unpack/<NCA>/1/bin/...` 是本仓库 Python 解析器生成的 CSV、JSON 和元数据镜像。脚本不解密 NCA，也不需要连接 HOME 账号/服务器。

## 2. 文本 DAT/TBL 是怎样转为 11 语言名称？

实现位置：
- `tools/home41_romfs_core.py`：`ahtb_labels()`、`dat_lines()`、`render_tokens()`；
- `tools/unpack_home41.py`：`export_one()` 的 `.dat` 与 `.tbl` 分支。

`itemname.tbl` 是 `AHTB` 格式，按 `<u64 hash, u16 length, NUL 结尾 UTF-8 label>` 读取，并对 label 的 UTF-8 字节重新计算变体 FNV64（basis `0xCBF29CE484222645`，prime `0x100000001B3`）。

`itemname.dat` 先解码每条字符串的 UTF-16 单元：初始 `key=(0x7C89 + index*0x2983)&0xFFFF`，每读取一个单元进行 `decoded_u16 = stored_u16 ^ key`，随后 key 循环左移 3 bit。原始脚本保留行号、`flags`、`source_offset`，并处理控制码。把同一行的 DAT 文本与 TBL 标签配对得到 `index,label,hash_fnv64,text,flags,source_offset`。

最后使用 **同一个数字 index** 在 11 种语言之间连接为 2685 行。禁止按中英文文字或 hash 与 PML hash 错误关联：同名、翻译差异和空名称都可能存在。

例如 `ITEMNAME_001`、`2C73258BE8795B1D` → 简中 `大师球`、英文 `Master Ball`、日语 `マスターボール`。

## 3. PML item.dat 怎样算出记录偏移与属性？

原始 `item.dat`：61,092 字节，SHA256 `4f5edd3f0ca8ed0c60ceb91fda0c5385f20ec986a66dcf4aa68d1c145903a1a2`。

| 文件偏移 | 值 | 含义 |
|---|---:|---|
| `0x00 u16` | 1829 | 有效逻辑 ItemID（0–1828） |
| `0x02 u16` | 1832 | 索引槽容量，末 3 项填充 |
| `0x04 u16` | 1166 | 独立物理记录数 |
| `0x20` | 9 个 u16 | Pouch 物理记录分类计数 |
| `0x40 u32` | 5124 | 物理记录数据起点 |
| `0x44` | 1832 个 u16 | `lookup[item_id]` → 物理记录索引 |
| `0x1404` | 1166×48B | Item8 记录直到 EOF |

```c
uint16_t count = read_u16(itemdat + 0x00);       // 1829
uint16_t capacity = read_u16(itemdat + 0x02);    // 1832
uint16_t record_count = read_u16(itemdat + 0x04);// 1166
uint32_t base = read_u32(itemdat + 0x40);        // 5124
if (item_id >= count) reject();
uint16_t record_index = read_u16(itemdat + 0x44 + 2*item_id);
if (record_index >= record_count) reject();
const uint8_t *rec = itemdat + base + 0x30*record_index;
```

与原生 ELF `main+0x4FD784` Getter 一致；**不要**写成 `itemdat + 5124 + item_id*48`。例如 `ItemID=112` 的 `record_index=86`，真正数据偏移 `5124 + 86*48 = 9252`。

48B 相对偏移主要为：

| 记录内偏移 | 类型 | 输出属性 |
|---|---|---|
| `0x00` | u32 LE | `price_u32` |
| `0x04` | u32 LE | `price_watts_native_u32` |
| `0x08` | u32 LE | `price_alternate_native_u32` |
| `0x11` | u8低4位 | `pouch_index`（0..8） |
| `0x13` | u8 | `effect_field_u8` |
| `0x15` | u8 | `can_use_on_pokemon` |
| `0x1A` | **signed i16 LE** | `sprite_native_i16` |
| `0x1C` | u8 | `group_type_u8` |
| `0x1D` | u8 | `group_index_u8` |

Native 的 ItemSprite 由 `main+0x2C3054` 读取，非负值格式化为 `item_%04d^o`；负值回退 `item_dummy^o`。此键不是 atlas 中已定位的图片文件路径。

`item_hash_to_index.dat` 每行 16B，**不**使用文本的 FNV64 标签哈希。把它以行号 `0..1828` 对应到 PML 逻辑 ID，并保留 hash/index 原始值。索引表额外第 1829 行不是第 1830 个可用的 ItemID。

## 4. 一条命令重建：只需 PokeHome_Resources

已经具有原始 HOME 4.1.0 RomFS 的 `4.1.0` 分支仓库中运行（Python 3.10+）：

```bash
python tools/rebuild_home41_from_romfs.py
```

这将写入 `derived/4.1.0/item_catalog/`：

```text
HOME41_itemname_2685_11lang.csv       2685×17
HOME41_itemid_1829_pml_crosswalk.csv  1829×25
HOME41_item_catalog_validation.json   来源、行数、文件 SHA256 和校验摘要
```

可选目标路径：

```bash
python tools/rebuild_home41_from_romfs.py --source-root . --out-dir ./my_item_csv
```

已有 `Unpack` 镜像与 manifest 时可以跳过重新解码（**仍检查 11 组原始 DAT/TBL 的标签、哈希、文字、flags、source_offset**）：

```bash
python tools/rebuild_home41_from_romfs.py --skip-unpack
```

只从已经验证的镜像 CSV 重新构建：

```bash
python tools/build_home41_item_catalog.py --source-root . --out-dir derived/4.1.0/item_catalog
```

脚本会拒绝源 `item.dat` SHA256、11 语种记录数/索引/标签哈希、PML 索引域、padding、价位/类别统计等不符合 4.1.0 已验证数据的情形。若 `main.elf` 存在会验证原生 ELF SHA256 `bdb558f795710a89aee1af7ed3b5de359a4ca0b4fef6dcdca62e597b9d45df7a`。成功时写 JSON 报告；未通过时抛异常并非虚报完成。

### Windows PowerShell

```powershell
git clone --branch 4.1.0 https://github.com/969981/PokeHome_Resources.git
Set-Location PokeHome_Resources
py -3 tools/rebuild_home41_from_romfs.py --out-dir derived/4.1.0/item_catalog
```

**注意**：此仓库含较多大资源文件；若仅 sparse checkout 了 `tools/` 而缺少 NCA 的原始 11 语言 `.dat/.tbl` 与 `item.dat`，脚本会明确报缺失，绝不会静默填造数据。

## 5. 实际关联校验、数据边界与 ELF

截至 2026-11-10，已独立核验已提交的双 CSV：名称表 2685 行 / 17 列，PML 表 1829 行 / 25 列；所有 1829 个 PML ID 的中文、英文、标签哈希、`record_index`、`source_record_offset` 与原始 48B 字段重新计算结果一致（**0 项发现不一致**）。1166 条唯一物理记录、663 个附加默认映射、683 个图标回退 ID。

Pouch 物理记录数：Medicine 37、Balls 27、Battle 10、Berries 53、Items 640、TMs 200、Treasures 20、Ingredients 25、Key 154；合计 1166。这里“物理记录”不等于游戏存档中实际背包库存。

原生函数证据点：
- `main+0x502104` 证明 `item.dat` 路径引用；
- `main+0x6979C` 与 `+0x6986C` 证明独立哈希索引文件引用及 16B 步长；
- `main+0x4FD784` 为 ItemID→记录指针；
- `main+0x4FD0B8` 为 26 路 Item Getter；
- `main+0x266D30` 为 Pouch/Bag 消费者；
- `main+0x2C3054` 为 sprite 格式化消费者。
