# P10 · Sword / Shield 1.3.2 Item8 状态治疗、PP Up 与 EV Setter 静态闭环

> 研究日期：2026-10-14。原始二进制仍只保留在用户 Library；本报告只公布地址、指令、验证脚本与结构化审计结果。所有地址均为 ELF main-relative RVA。**无实机动态验证、无同 Build 的剑盾 RomFS 道具表逐 ID 配对。**

## 2. Selector 26–30：异常状态治疗标志 → 状态清零 Setter

状态读取：`0x13B61C0 → 0x77B560 → 0x767F50`。游戏分别把当前状态枚举与下表的数字比较；当道具对应 selector 非零，才进入相应可用/执行分支。

| Selector | 游戏内状态枚举值 | 剑版可用条件读取 BL | 剑版执行分支读取 BL |
|---|---:|---|---|
| 26 | 2 | `0x13B61D0` | `0x13B6838` |
| 27 | 5 | `0x13B61E8` | `0x13B68AC` |
| 28 | 4 | `0x13B6200` | `0x13B6878` |
| 29 | 3 | `0x13B6218` | `0x13B6860` |
| 30 | 1 | `0x13B6230` | `0x13B6804` |

**实际写入闭环：** `main+0x13B6898 BL 0x77B580` → `0x77B584 MOV W1,WZR` → `0x77B588 B 0x76EB60` → `0x76EC10 STR W20,[X8,#0x3C]`，清除 32-bit 状态字段。盾版高层调用点为 `0x13B68C8`。这里已证明“对应状态枚举 + 道具标志 + 清零写回”，但**尚未独立证明五个内部状态枚举值分别对应哪一种中文异常名称**，不根据编号猜测。

## 3. Selector 45–48：PP 上限阶段和 PP 恢复作用域

- `45` 与 `46` 是 PP 上限提升（PP Up/PP Max）相关控制标志：剑版读取 `0x13B6A0C` / `0x13B6A68`；与现有 PP Up 阶段（0..3）比较及增量 +1/+3 的控制流相连。
- 剑版 `0x13B6AB4 → 0x77B860 → 0x770E80 → 0x770F3C STRB W20,[X8,#0x26]`，按招式槽位 0..3 写入 PP Up 阶段，最终上限裁剪为 3。
- `47` 与 `48` 分别进入单招式槽位和遍历多个招式槽位的 PP 恢复判断（剑版 `0x13B6AE4`、`0x13B6B60`）。恢复量仍读 `67` 并送至 P9 验证过的 `0x77B770`。需要进一步用 RomFS 值对应 PP Up、PP Max 和 PP 恢复道具，才能严格命名具体 Item ID。

## 4. Selector 50–55、60–65：EV/基础点数六通道

每一项均有两个 Item8 参数：`50..55` 为是否执行该项调整的非零控制标志；`60..65` 为使用 `LDRSB` 读取的有符号 8-bit 调整量。读取当前基础点数 `0x77A6E0`，写入执行函数 `0x77A8A0`，并经过 `0x77AB70` 裁剪辅助函数。

| 业务属性 | 状态枚举 | 开关 selector | 有符号 delta selector | 剑版 delta 读取 BL | 剑版写入函数 BL | 最终原始字节写入 |
|---|---:|---:|---:|---|---|---|
| HP EV | 0 | 50 | 60 | `0x13B6D60` | `0x13B6E34` | `0x770488 STRB [X8,#0x1E]` |
| 攻击 EV | 1 | 51 | 61 | `0x13B6E68` | `0x13B6F28` | `0x7705D8 STRB [X8,#0x1F]` |
| 防御 EV | 2 | 52 | 62 | `0x13B6F50` | `0x13B700C` | `0x770728 STRB [X8,#0x20]` |
| 速度 EV | 5 | 53 | 63 | `0x13B7038` | `0x13B70F4` | `0x770B18 STRB [X8,#0x21]` |
| 特攻 EV | 3 | 54 | 64 | `0x13B7120` | `0x13B71DC` | `0x770878 STRB [X8,#0x22]` |
| 特防 EV | 4 | 55 | 65 | `0x13B7208` | `0x13B72AC` | `0x7709C8 STRB [X8,#0x23]` |

原生边界：`0xFC=252` 单项 EV 与 `0x1FE=510` 六项总量限制。剑版 `0x13B6DD8`、`0x13B6DF0`、`0x13B6E14` 及辅助函数 `0x77AB88` 有明确的 `CMP`。六个通道的写入入口为 `0x7703E0` / `0x770530` / `0x770680` / `0x770A70` / `0x7707D0` / `0x770920`，其跳表选择由 `0x77A8E0–0x77A8F0` 决定。

`56` 参与 EV 的附加处理/上限分支，**具体语义尚未闭合**。不要简单把其定义为“取消上限”。`57–59` 分别配合 `68–70` 用于友好度三档正向调整的条件筛选；P9 已闭合 `68–70` 的有符号增减及最终字节 Setter。

## 5. 方法和证据限制

复现脚本：`tools/swsh_132_item_effect_p10.py`。结构化输出：`derived/4.1.0/native_item_topics/swsh_132_item_effect_p10.json`。

本轮验证包括：原版 ELF SHA 和 Build ID；selector 参数原始指令（注意不只是 `MOVZ`，也可能是 `ORR W1,WZR,#imm`）；BL/B 静态目标；双版本高层 `+0x30` 差异；状态 `STR`、PP Up `STRB`、EV 六项 `STRB` 的操作码及偏移。P9 统计的“各 78 个 call 前 -8 为 MOVZ”的调用点是**严格子集**，不能把它理解成全部常量 selector 使用位置：有部分来源是 ORR-immediate，另外也有 `MOV W1` 更早于 call-8 的场景。

仍未完成：同 Build RomFS `bin/pml/item` 逐 ID 对照、运行时实际状态变更采样、其余未见直接立即数消费者的 selector 语义。动态调用链缺失不等于该字段无用。
