# HOME 4.1.0 Unpack — 开发任务清单与阶段验收

基准：`4.1.0`，源输入 `<NCA>/1` 的 **12,074** 个文件。所有任务须以真实文件实测为完成依据，禁止“代码写完 = 文件已经全部解包”。参照 [目标](UNPACK_GOAL.md)、[输出规范](UNPACK_OUTPUT_SPEC.md)、[AGENTS](../AGENTS.md)。

## 阶段总览

| 阶段 | 优先级 | 依赖 | 交付门槛 |
|---|---|---|---|
| P0 基线/镜像基础 | 最高 | 无 | 全源索引 + 目标路径预演 + 冲突报告 |
| P1 PML 与文字 | 最高 | P0 | 招式、种族、可解文本真实写入镜像目录 |
| P2 SARC/UI | 高 | P0 | SARC 成员完整提取，可解析的 UI 元数据 |
| P3 BNTX/图片 | 高 | P0、P2 | gzip 全覆盖、支持的 PNG 可验证 |
| P4 其他格式 | 中 | P0 | 分类输出、能力边界及未支持表 |
| P5 全量验证/发布 | 最高 | P1–P4 | 可重复全量运行和持久化交付 |

## P0 — 基线与调度器

- [x] **U00 仓库审计与文档基线**：核实已有工具、Git 树、输入规模；建立 `AGENTS.md`、目标/任务/命名规范。**本轮完成的仅为文档与目录说明**。
- [ ] **U01 完整源清单重建**：编写 inventory 扫描，逐文件输出 `source_path,size,sha256,extension,magic`；与 `derived/4.1.0/inventory/` 的已有 source blob 列表对齐（注意 Git blob SHA-1 不等同文件 SHA-256）。验收：RomFS 恰好记录 12,074 行，发现新增/缺失有差异报告。
- [ ] **U02 输出路径规划器**：构造镜像相对路径、处理复合扩展名、配对 DAT/TBL、处理文件名大小写折叠和输出碰撞；规划归档成员空间。验收：`--dry-run` 不写文件，所有源文件均有确定输出计划或明确原因，无静默覆盖。
- [ ] **U03 统一 CLI**：新建 `tools/unpack_home41.py`，实现 `--file / --kind / --all / --dry-run / --resume / --verify / --strict`，全部复用旧解析库；日志、错误和路径稳定。验收：Windows PowerShell/Linux 均可运行；中断恢复不会损坏已有文件。

## P1 — PML、文本与表格

- [ ] **U04 Waza**：复用 FlatBuffers 原始解析，输出 5,089 个 `.wazabin` 的 JSON；逐文件校验 root/vtable/原始字段边界，保持种类/招式 ID 的源证据。验收：5,089 行真实 status，所有转换产物均能追溯到源。
- [ ] **U05 Personal**：7 个 `.perbin` 依照已验证记录读取器输出 JSON，必要时 CSV；不凭未知字段冒充种族数值。验收：实际表内记录数量与当前仓库已有 Personal 导出交叉核对；解析错误进入错误表。
- [ ] **U06 Messages**：检测 `.dat` / `.tbl` 实际配对，核对 AHTB 标签 hash、文本行数、语言；`.dat→.csv`，`.tbl→.json`。未配对 DAT 用专用识别规则，不能强行解释文本。验收：1,583 DAT + 1,479 TBL 各有状态；在多个语言/地点/控制码样本上逐条还原。

## P2 — SARC 与 UI

- [ ] **U07 SARC 成员提取**：逐一检查 240 个 `.arc` 的 SARC/SFAT/SFNT，写同名 `.json` 索引、成员原始字节、SHA-256；拒绝危险归档成员路径。验收：每个可解析归档的成员数、大小和 SHA 与源内部计算一致；失败不以空目录伪装成功。
- [ ] **U08 FLYT/FLAN/UIKIT**：归档内 `.bflyt/.bflan` 分节、Pane 名、动画结构；`*_lyt.bin/*_uikit.bin` FlatBuffers 结构 JSON。验收：至少包含 `mtt_moving`、`cursor` 实际样本；未恢复 schema 的字段保持候选状态。

## P3 — 纹理与可用图像

- [ ] **U09 gzip + BNTX**：逐一校验 3,538 个 `.bntx.gz` 解压后确实为 BNTX，写镜像目录下同主体 `.bntx`；对既有 `.bntx` 同等识别。验收：CRC/尺寸和解压错误清楚记录；无法 gzip 的项目不能被计作解压成功。
- [ ] **U10 PNG 解码**：复用已有 RGBA8、BC1、BC3、BC4、BC5；增加真实 BNTX array/多纹理/格式统计；ASTC、BC7、BC6 列为后续解码专项，未经实测不声称支持。验收：成功 PNG 的签名、宽高、像素负载真实有效，BC5 标记为通道可视化而非最终着色；不支持项有 component_status。
- [ ] **U11 非普通纹理的 SARC BNTX**：给 SARC 成员内 BNTX 建立可追溯关系并转换可支持图片。验收：源 ARC → 成员路径 → 图片的哈希链可查，输出路径无碰撞。

## P4 — 边界格式

- [ ] **U12 其他二进制发现**：`.prmb`、`.bfbs`、其他 `.bin` 逐个按 magic/引用上下文分类；`.bfbs` 优先确认是否可恢复 FlatBuffers 类型定义。验收：只在字段结构经验证时输出 JSON，未确认的写 `unsupported`。
- [ ] **U13 音频/着色器/字体**：检查 `.bnk/.pck/.bnsh/.bffnt/.BFOTF`；优先索引、引用关系与合法可提取子项，外部解码器需固定版本并提供交叉验证。验收：所有文件入 manifest；不造伪 WAV/PNG；不额外提交字体副本。

## P5 — 全量验证与发布

- [ ] **U14 Manifest 与冲突验收**：全源文件一一映射，保存原始与输出 SHA-256、parser 版本、状态、错误；提供 `--verify --strict`。验收：12,074 行，不存在遗漏或未报告冲突；多次运行不改写未变化产物；所有 `failed` 可定位。
- [ ] **U15 测试矩阵**：大小写碰撞、同名 DAT/TBL、畸形 FlatBuffers、SARC 路径穿越、gzip 炸弹、纹理尺寸越界、原子写入、断点续跑、缺失依赖、真实源样本。验收：单测/集成测试均提供命令和退出码，真实输出至少覆盖每种已宣称支持的类型。
- [ ] **U16 大规模运行与发布**：按 `messages/pml/archives/textures/other` 分批跑；先测大小再决定提交 Git/LFS/Release；持续核对分片与 manifest，必要时设置 GitHub Actions 手工分组工作流。验收：文档提供永久路径、各分批源文件范围、实际已发布产物数量与 SHA；临时 Artifact 不算长期发布。
- [ ] **U17 最终收官**：重新扫描仓库，核对输入未修改、所有源行都有状态、镜像文件可定位，更新 `README_CONVERSION.md` 与进度表。验收：客观列出 converted/partial/unsupported/failed，不把未知数据当作已完成语义解析。

## 任务依赖与顺序

```text
U00(完成：文档)
  └─ U01(源清单) ─ U02(路径规则) ─ U03(调度器)
                             ├─ U04/U05/U06(PML+文字)
                             ├─ U07 ─ U08 ─ U11(SARC/UI)
                             ├─ U09 ─ U10(纹理)
                             └─ U12/U13(其他)
                                      ↓
                            U14(索引验证)
                                      ↓
                         U15(测试) ─ U16(发布)
                                      ↓
                                U17(收官)
```

建议第一个实现 PR/提交只做 **U01–U03 + 典型文件样例**，跑通确定性的路径和状态机后，再分格式并行开发。不要先成批转换 12,074 个文件后才发现命名冲突。

## 实施记录模板

每次更新对应 Uxx 的复选框前，必须在提交说明或进度记录中写：

- 输入格式与真实文件范围/个数；
- 执行命令、环境、退出码、耗时及成功/失败数量；
- 产物路径（Git commit / LFS 对象 / Release）与校验方法；
- 解析证据：格式签名、偏移、字段/像素限制；
- 遗留 unsupported、failed 的实际路径、阻塞原因和下一步。
